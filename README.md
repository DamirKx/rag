# RAG Retrieval: поиск по законодательству Республики Казахстан

Поисковая подсистема RAG для нормативно-правовых актов (НПА) Республики Казахстан: по вопросу находит фрагмент
закона и возвращает его с названием акта, номером статьи и ссылкой на adilet.zan.kz. Проект посвящён
**этапу поиска** (retrieval) — генерация ответа языковой моделью не реализуется.

Поиск двухэтапный: гибрид лексического (BM25) и векторного (E5 + FAISS) поиска отбирает кандидатов,
реранкер cross-encoder переупорядочивает их. Модель эмбеддингов и реранкер дообучены на данных предметной
области, параметры всех методов подобраны на validation.

## Результаты

Тестовая выборка — 737 вопросов, поиск по 10 402 фрагментам 14 НПА (русская часть датасета Adilet Legal QA).

| Метод | MRR@10 | Hit@1 | Hit@10 |
|---|---|---|---|
| BM25 (`rank_bm25`, настройки по умолчанию) | 0,538 | 0,445 | 0,704 |
| BM25 со стеммингом и подобранными $k_1$, $b$ | 0,580 | 0,489 | 0,745 |
| Dense: `multilingual-e5-small` без дообучения | 0,518 | 0,421 | 0,733 |
| Dense: `multilingual-e5-small`, дообученная (3 запуска) | 0,625 ± 0,001 | 0,515 | 0,824 |
| Hybrid: дообученная e5 + BM25 (RRF) | 0,656 | 0,558 | 0,847 |
| + реранкер `bge-reranker-v2-m3` без дообучения | 0,715 | 0,628 | 0,879 |
| **+ реранкер `bge-reranker-v2-m3`, дообученный** | **0,763** | **0,691** | **0,887** |

Строки с реранкером посчитаны при более глубоких списках первого этапа (по 200 кандидатов у каждого метода);
при них гибрид без реранкера даёт MRR@10 = 0,660. Нужный фрагмент закона (а не конкретный чанк) итоговая система
ставит на 1-е место в 80,5% вопросов. Подробности, методика и все эксперименты — в [REPORT.md](REPORT.md).

## Методы

1. **Лексический поиск — Okapi BM25** (`src/retriever.py`). Собственная реализация на разреженных матрицах
   `scipy.sparse` (в 220 раз быстрее `rank_bm25`, с настройками по умолчанию оценки совпадают). Юридическая
   токенизация сохраняет номера («221-VII», «28-1», «122-бап»); нормализация словоформ (`src/text_norm.py`):
   стеммер Snowball, лемматизация `pymorphy3` или обрезка до N букв — номера при этом не меняются.
2. **Векторный поиск** — модель `multilingual-e5-small` (префиксы `query: ` / `passage: `) и точный индекс
   FAISS `IndexFlatIP`.
3. **Гибрид — Reciprocal Rank Fusion** с весами, подобранными на validation.
4. **Переранжирование** — cross-encoder (`src/reranker.py`) переоценивает топ-N кандидатов любого метода, читая
   вопрос и фрагмент вместе; длинные документы оцениваются по окнам (максимум по окнам).

**Чанкинг:** окно 500 символов с перекрытием 50 (`src/chunking.py`; там же структурный чанкер по статьям
«Статья N.» / «N-бап.»). **Метрики:** MRR@10, Hit@k, Recall@k (`src/eval.py`).

## Модели

| Модель | Роль | Где взять |
|---|---|---|
| `models/e5-small-adilet-rus` | эмбеддинги, **по умолчанию** | `notebooks/finetune_e5.ipynb` |
| `intfloat/multilingual-e5-small` | эмбеддинги без дообучения (если дообученной нет) | Hugging Face |
| `models/reranker-bge-m3-adilet-rus` | реранкер, **по умолчанию** | `notebooks/finetune_reranker.ipynb` |
| `BAAI/bge-reranker-v2-m3` | реранкер без дообучения (если дообученного нет) | Hugging Face |
| `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1` | быстрый реранкер (в 7 раз быстрее, для CPU) | Hugging Face |

Дообученные модели в git не хранятся (`models/` в `.gitignore`). Если папки нет, `ask.py`, веб-демо и скрипты
оценки автоматически берут исходную модель с Hugging Face.

## Установка

```bash
git clone https://github.com/DamirKx/rag.git
cd rag
python -m venv .venv
.venv\Scripts\activate          # Windows; Linux / macOS: source .venv/bin/activate
pip install -r requirements.txt
python prepare_adilet_data.py --lang all --test-size 200
```

`prepare_adilet_data.py` скачивает датасет `olzhasAl/adilet-legal-qa-kz` с Hugging Face, очищает тексты
и формирует файлы вопросов и корпусов в `data/adilet/`.

## Поиск

### Консоль
```bash
python ask.py                   # гибридный поиск (по умолчанию)
python ask.py --mode bm25       # или dense
python ask.py --rerank          # с реранкером (дообученным, если он есть в models/)
python ask.py --rerank --reranker cross-encoder/mmarco-mMiniLMv2-L12-H384-v1 --rerank-pool 20
python ask.py --generate        # + ответ qwen2.5:3b по найденным фрагментам (нужна запущенная Ollama)
```
Во время работы: `:mode dense|bm25|hybrid`, `:rerank on|off`, `:answer on|off`, выход — `q`. `ask.py` ищет по
фрагментам законов целиком (~6 тыс. символов) с настройками BM25 и гибрида по умолчанию: параметры, подобранные
для чанков, на длинных фрагментах хуже.

Ответ модели строится так же, как в веб-демо и в `eval_generation.py`: гибридный поиск по чанкам 500 символов,
реранкер, 3 лучших чанка, затем проверка ответа по тексту закона. Над обычной выдачей выводятся ответ со ссылками
[n] и источниками (закон, статья, ссылка на adilet.zan.kz) либо отказ / цитата закона, если ответ не прошёл проверку.

### Веб-демо
```bash
streamlit run app.py            # http://localhost:8501
```
- выбор языка (рус / каз), метода (Hybrid / Dense / BM25) и модели эмбеддингов;
- поиск по чанкам 500 символов: подсветка слов запроса, закон, номер статьи, ссылка на adilet.zan.kz;
- фильтр по законам и вкладка «Сравнение методов» (топ-3 каждого метода на один вопрос);
- переключатель «Реранкер»; размер пула берётся из `data/adilet/reranker_eval_{lang}.json`.

Параметры BM25 и гибрида подхватываются из `bm25_tuning_{lang}.json` и `hybrid_tuning_{lang}.json`.
При первом запуске эмбеддинги корпуса вычисляются (на GPU — меньше минуты), затем берутся из кэша
`data/adilet/cache/`; в ключ кэша входят отпечатки модели и текстов, поэтому устаревший кэш не используется.

## Воспроизведение экспериментов

Шаги по порядку — каждый следующий использует результаты предыдущего:

```bash
python run_adilet_eval.py --lang rus --test-size 100 --top-k 3   # 1. сравнение чанкинга и моделей (протокол A)
# 2. notebooks/finetune_e5.ipynb → Run All (GPU, ~30–40 мин):       разбиение train/val/test, дообучение e5
python tune_bm25.py --lang rus                                    # 3. подбор BM25 (~4 мин)
python tune_hybrid.py --lang rus                                  # 4. подбор весов гибрида
python eval_reranker.py --lang rus                                # 5. реранкеры поверх гибрида (~15 мин на GPU)
# 6. notebooks/finetune_reranker.ipynb в Google Colab (T4, ~1 ч):  дообучение реранкера
python eval_reranker.py --lang rus --rerankers models/reranker-bge-m3-adilet-rus   # 7. досчитать дообученный
pytest                                                            # тесты
```

Все подборы выполняются на validation, test считается один раз для итоговой таблицы. Результаты сохраняются
в `data/adilet/*.json`.

**Дообучение реранкера в Colab.** На Google Drive нужно заранее загрузить дообученную e5 — архив
`e5-small-adilet-rus.zip` в `MyDrive/` или `MyDrive/rag/`; остальное (код, пакеты, датасет) ноутбук скачивает сам.
Итоговая модель сохраняется на Drive в `MyDrive/rag/models/reranker-bge-m3-adilet-rus/`. При скачивании папки
Drive отдаёт веса отдельным файлом `model-001.safetensors` — его нужно положить в ту же папку проекта
`models/reranker-bge-m3-adilet-rus/` и переименовать в `model.safetensors`.

## Ограничения

- **Происхождение вопросов.** Вопросы датасета сгенерированы по тем же текстам, по которым идёт поиск, — метрики,
  вероятно, выше, чем на реальных пользовательских запросах.
- **Автоматические эталоны.** Эталонный чанк определяется по совпадению слов ответа с текстом; доля неверных
  эталонов — около 3–5%. В протоколе A (`run_adilet_eval.py`) разметка проще (первые 45 символов ответа),
  поэтому его цифры напрямую не сравниваются с таблицей выше.
- **Чанк не знает своей статьи.** Окно 500 символов часто отрезает заголовок статьи; это главная причина ошибок
  итоговой системы (REPORT.md, раздел 7.10).
- **Один язык дообучения.** Дообучение и подбор параметров выполнены для русской части; казахская использует
  исходные модели и BM25 по умолчанию. Реранкер дообучен в одном запуске (разброс по seed не оценён).
- **Название акта в датасете.** Поле `source_title` не соответствует тексту у 9 из 14 документов; веб-демо берёт
  названия из шапки страницы adilet.zan.kz, `prepare_adilet_data.py` и бенчмарк — из поля датасета.
- **Структурный чанкер** (`get_structural_chunks`) в бенчмарке Adilet пока не используется — только в `run_real_data.py`.
