# RAG Retrieval: поиск по законодательству Республики Казахстан

Поисковая подсистема RAG для нормативно-правовых актов (НПА) Республики Казахстан: по вопросу находит фрагмент
закона и возвращает его с названием акта, номером статьи и ссылкой на adilet.zan.kz. По желанию локальная
языковая модель (Qwen2.5-3B через Ollama) формулирует по найденным фрагментам ответ со ссылками; ответ,
не подтверждённый текстом закона, не показывается.

Поиск двухэтапный: гибрид лексического (BM25) и векторного (E5 + FAISS) поиска отбирает кандидатов,
реранкер cross-encoder переупорядочивает их. Модель эмбеддингов и реранкер дообучены на данных предметной
области, параметры всех методов подобраны на validation.

## Результаты

Тестовая выборка — 737 вопросов, поиск по 10 402 фрагментам 14 НПА (русская часть датасета Adilet Legal QA).

| Метод | MRR@10 | Hit@1 | Hit@10 |
|---|---|---|---|
| BM25 (`rank_bm25`, настройки по умолчанию) | 0,538 | 0,445 | 0,704 |
| BM25 со стеммингом и подобранными $k_1$, $b$ | 0,580 | 0,489 | 0,745 |
| Dense: `multilingual-e5-small` без дообучения | 0,518 | 0,421 | 0,733 |
| Dense: `multilingual-e5-small`, дообученная (3 запуска) | 0,625 ± 0,001 | 0,515 | 0,824 |
| Hybrid: дообученная e5 + BM25 (RRF) | 0,656 | 0,558 | 0,847 |
| + реранкер `bge-reranker-v2-m3` без дообучения | 0,715 | 0,628 | 0,879 |
| **+ реранкер `bge-reranker-v2-m3`, дообученный** | **0,763** | **0,691** | **0,887** |

Строки с реранкером посчитаны при более глубоких списках первого этапа (по 200 кандидатов у каждого метода);
при них гибрид без реранкера даёт MRR@10 = 0,660. Нужный фрагмент закона (а не конкретный чанк) итоговая система
ставит на 1-е место в 80,5% вопросов. Подробности, методика и все эксперименты — в [REPORT.md](REPORT.md).

**Генерация ответа** (тот же test; в условии no_gold из выдачи удалён фрагмент закона, по которому составлен
вопрос, — правильное поведение там отказ):

| Защита от галлюцинаций | Выдан ответ | token-F1 | no_gold: выдан ответ |
|---|---|---|---|
| Только промпт | 84,7% | 0,465 | 39,2% |
| + порог реранкера | 81,7% | 0,469 | 25,5% |
| + проверка ответа по тексту закона и соответствия вопросу | **68,0%** | **0,512** | **16,7%** |
| *Первая версия генерации, полная защита* | *55,9%* | *0,511* | *19,0%* |

Без проверки у 9,6% вопросов ответ содержит сведения, которых нет во фрагментах; в выданных после проверки ответах таких нет
(в том числе при ручной проверке 50 ответов первой версии и 12 ответов доработанной). Оставшаяся ошибка — ответ из соседнего
пункта того же текста (5 из 25 при ручной проверке), поэтому к ответу всегда прилагается источник. Доработанная версия
получает чанк с окружающим текстом, переспрашивает модель при ответе без текста и убирает ссылки на несуществующие
фрагменты; ответ по нужному чанку — 47,3% вопросов вместо 35,0%. Подробно — REPORT.md, разделы 7.11–7.12.

## Методы

1. **Лексический поиск — Okapi BM25** (`src/retriever.py`). Собственная реализация на разреженных матрицах
   `scipy.sparse` (в 220 раз быстрее `rank_bm25`, с настройками по умолчанию оценки совпадают). Юридическая
   токенизация сохраняет номера («221-VII», «28-1», «122-бап»); нормализация словоформ (`src/text_norm.py`):
   стеммер Snowball, лемматизация `pymorphy3` или обрезка до N букв — номера при этом не меняются.
2. **Векторный поиск** — модель `multilingual-e5-small` (префиксы `query: ` / `passage: `) и точный индекс
   FAISS `IndexFlatIP`.
3. **Гибрид — Reciprocal Rank Fusion** с весами, подобранными на validation.
4. **Переранжирование** — cross-encoder (`src/reranker.py`) переоценивает топ-N кандидатов любого метода, читая
   вопрос и фрагмент вместе; длинные документы оцениваются по окнам (максимум по окнам).

**Чанкинг:** окно 500 символов с перекрытием 50 (`src/chunking.py`; там же структурный чанкер по статьям
«Статья N.» / «N-бап.»). **Метрики:** MRR@10, Hit@k, Recall@k (`src/eval.py`).

## Модели

| Модель | Роль | Где взять |
|---|---|---|

| `models/reranker-bge-m3-adilet-rus` | реранкер, **по умолчанию** | `notebooks/finetune_reranker.ipynb` |
| `BAAI/bge-reranker-v2-m3` | реранкер без дообучения (если дообученного нет) | Hugging Face |

| `MoritzLaurer/mDeBERTa-v3-base-xnli-multilingual-nli-2mil7` | проверка следования ответа из фрагмента (NLI, CPU, необязательна) | Hugging Face |

Дообученные модели в git не хранятся (`models/` в `.gitignore`). Если папки нет, `ask.py`, веб-демо и скрипты
оценки автоматически берут исходную модель с Hugging Face.

## Поиск

### Консоль
```bash
python ask.py                   # гибридный поиск (по умолчанию)
python ask.py --mode bm25       # или dense
python ask.py --rerank          # с реранкером (дообученным, если он есть в models/)
python ask.py --rerank --reranker cross-encoder/mmarco-mMiniLMv2-L12-H384-v1 --rerank-pool 20
python ask.py --generate        # + ответ qwen2.5:3b по найденным фрагментам (нужна запущенная Ollama)
```
Во время работы: `:mode dense|bm25|hybrid`, `:rerank on|off`, `:answer on|off`, выход — `q`. `ask.py` ищет по
фрагментам законов целиком (~6 тыс. символов) с настройками BM25 и гибрида по умолчанию: параметры, подобранные
для чанков, на длинных фрагментах хуже.

Ответ модели строится так же, как в веб-демо и в `eval_generation.py`: гибридный поиск по чанкам 500 символов,
реранкер, 3 лучших чанка с окружающим текстом, затем проверка ответа по тексту закона. Над обычной выдачей выводятся ответ со ссылками
[n] и источниками (закон, статья, ссылка на adilet.zan.kz) либо отказ / цитата закона, если ответ не прошёл проверку.

### Веб-демо
```bash
streamlit run app.py            # http://localhost:8501
```
- выбор языка (рус / каз), метода (Hybrid / Dense / BM25) и модели эмбеддингов;
- поиск по чанкам 500 символов: подсветка слов запроса, закон, номер статьи, ссылка на adilet.zan.kz;
- фильтр по законам и вкладка «Сравнение методов» (топ-3 каждого метода на один вопрос);
- переключатель «Реранкер»; размер пула берётся из `data/adilet/reranker_eval_{lang}.json`;
- переключатель «Ответ языковой модели» (нужна Ollama с `qwen2.5:3b`); пороги проверки ответа — из
  `data/adilet/generation_eval_{lang}.json`.
- страница открывается за ~2 с: библиотеки и модели (e5, индекс, BM25, реранкер) загружаются в фоне, пока
  набирается вопрос; при включении ответа модели Qwen заранее загружается в Ollama. Результат поиска и ответ
  запоминаются для пары «вопрос + настройки», поэтому клики по интерфейсу не повторяют поиск.
- видеопамять (4 ГБ): e5 векторизует вопросы на процессоре (выдача на 300 вопросах test та же, 18 мс на гибридный
  поиск), реранкер переносится на видеокарту уже в fp16, после запроса PyTorch возвращает лишнюю память.
  Так Qwen целиком помещается на видеокарту (37/37 слоёв, всего занято ~3,4 ГБ). Раньше реранкер держал
  ~2,5 ГБ вместо 1,1 ГБ, часть Qwen уходила в обычную память, и ответ модели был в 1,5–2 раза медленнее:

  | | до | после |
  |---|---|---|
  | видеопамять (поиск + Qwen) | 3,9 ГБ, часть — в обычной памяти | 3,4 ГБ |
  | поиск с реранкером | 0,60 с | 0,17 с |
  | ответ Qwen | 6,4 с | 3,8 с |
  | проверки ответа | 0,32 с | 0,03 с |

**Законы для граждан.** Корпус актуальных актов (Конституция, Гражданский, Трудовой, Семейный и Социальный кодексы,
законы о жилье и о защите прав потребителей) выбирается в боковой панели. Новые PDF с adilet.zan.kz кладутся
в `data/laws/`, затем `python prepare_laws.py`. Для этого корпуса веб-демо дописывает к вопросу термины закона
(словарь «разговорное → юридическое», `src/query_expansion.py`: «уволиться» → «расторжение трудового договора по
инициативе работника»), использует исходный реранкер `bge-reranker-v2-m3` и свои пороги — их выбрал
`eval_laws_colloquial.py` на 59 вопросах обычным языком (`data/laws/colloquial_questions.json`, REPORT 7.15).
Проверка чисел для законов понимает числа словами («двадцать четыре календарных дня» = «24 дня», `src/number_words.py`),
а ответ из одного числа («24 [1]») модель переписывает полным предложением по повторному запросу. qwen3:4b и русская
адаптация Qwen2.5-3B (RuAdapt) отвечали чаще, но показали неверные ответы, которые не поймала ни одна проверка, поэтому
модель ответа осталась прежней (REPORT 7.16). Если модель не ответила, а поиск уверен, веб-демо показывает 1–2 пункта
закона, ближайших к вопросу, дословно (REPORT 7.17). Метрики выше относятся к датасету Adilet; качество на корпусе законов измерено отдельно (REPORT 7.15).

**Трассировка (Langfuse).** Если заданы ключи, каждый запрос веб-демо (вкладка «Результаты») и `ask.py`
записывается отдельной трассой с этапами — у каждого своё время на временной шкале Langfuse:

```
web-demo / ask-cli                  вопрос, настройки, итоговый ответ или найденные статьи
├─ load-models                      загрузка индекса и моделей; cold_start = true при первой загрузке
├─ search                           результат поиска (закон, статья, оценка)
│  ├─ hybrid | dense | bm25         выбранный метод
│  │  ├─ embed-query                векторизация вопроса (модель, устройство)
│  │  ├─ bm25-index-build           построение BM25 при первом запросе (холодный старт)
│  │  ├─ dense-faiss, bm25, rrf     пулы кандидатов; у результата RRF — место в списках Dense и BM25
│  ├─ law-filter                    фильтр «Искать только в законах»
│  └─ reranker                      оценки cross-encoder и место каждого фрагмента до переранжирования
├─ context                          фрагменты для модели (чанки с окружающим текстом)
└─ answer                           статус ответа
   ├─ retrieval-gate                порог уверенности поиска (WARNING — модель не вызывалась)
   ├─ llm, llm-retry                промпт, ответ, токены, время Ollama (load_s — загрузка модели), токенов/с,
   │                                стоимость $0, доля Qwen на видеокарте (WARNING, если меньше 100%); у повтора — причина
   └─ verification                  итог и причины отклонения (WARNING — ответ не показан)
      └─ citations, numbers, sentence-support, relevance, entailment
```

В metadata трассы — `resources`: время и процессорное время запроса, оперативная память процесса и компьютера,
видеопамять карты и PyTorch, размещение Qwen в Ollama. Этап load-models показывает видеопамять после загрузки моделей.
Запросы одной вкладки браузера (одного запуска `ask.py`) объединены в сессию.
У трассы с ответом модели — оценки (Scores), по ним в Langfuse можно фильтровать трассы и строить графики:
`retrieval_top_score` (уверенность поиска), `sentence_support` (опора худшего предложения на текст закона),
`answer_relevance`, `entailment` (если проверка включена), `answer_status` (answered / refused / no_context /
unverified) и `answer_shown` (1 — ответ показан; при 0 в комментарии — причины). Это итоги тех же проверок, что
решают, показывать ли ответ; облачные LLM-оценщики Langfuse не используются. Под ответом в веб-демо — кнопки 👍/👎:
оценка `user_feedback` (1/0) ставится на трассу ответа, повторный клик её перезаписывает.

**Эксперимент Langfuse.** `python langfuse_experiment.py` (в окне с ключами; веб-демо остановить — нужна видеокарта)
загружает первые 50 вопросов test в набор данных `adilet-test-rus-50` и прогоняет их через систему. Оценки
вопроса: эталонный чанк в контексте модели, ответ показан, token F1 и ROUGE-L с эталоном, ответ по эталонному
фрагменту; средние — оценки запуска. Запуски сравниваются в Langfuse (Datasets → набор → Runs) и копятся в
`data/adilet/langfuse_experiment_rus.json`. `--run-name` — подпись запуска, `--dry-run` — проверка без отправки. Вкладка «Сравнение методов» и оценка
(`eval_generation.py`, `tune_*.py`) не трассируются: этапы пишутся только внутри открытой трассы. Без ключей
ничего никуда не отправляется:
```powershell
$env:LANGFUSE_PUBLIC_KEY="pk-lf-..."; $env:LANGFUSE_SECRET_KEY="sk-lf-..."
$env:LANGFUSE_BASE_URL="https://cloud.langfuse.com"   # Langfuse Cloud или адрес своего сервера
```

Параметры BM25 и гибрида подхватываются из `bm25_tuning_{lang}.json` и `hybrid_tuning_{lang}.json`.
При первом запуске эмбеддинги корпуса вычисляются (на GPU — меньше минуты), затем берутся из кэша
`data/adilet/cache/`; в ключ кэша входят отпечатки модели и текстов, поэтому устаревший кэш не используется.

## Воспроизведение экспериментов

Шаги по порядку — каждый следующий использует результаты предыдущего:

```bash
python run_adilet_eval.py --lang rus --test-size 100 --top-k 3   # 1. сравнение чанкинга и моделей (протокол A)
# 2. notebooks/finetune_e5.ipynb → Run All (GPU, ~30–40 мин):       разбиение train/val/test, дообучение e5
python tune_bm25.py --lang rus                                    # 3. подбор BM25 (~4 мин)
python tune_hybrid.py --lang rus                                  # 4. подбор весов гибрида
python eval_reranker.py --lang rus                                # 5. реранкеры поверх гибрида (~15 мин на GPU)
# 6. notebooks/finetune_reranker.ipynb в Google Colab (T4, ~1 ч):  дообучение реранкера
python eval_reranker.py --lang rus --rerankers models/reranker-bge-m3-adilet-rus   # 7. досчитать дообученный
ollama pull qwen2.5:3b && python eval_generation.py --no-nli      # 8. генерация ответа (~2 ч на RTX 3050 Ti; без --no-nli ещё ~2 ч на CPU)
python prepare_laws.py                                            # 9. корпус актуальных законов из data/laws/*.pdf
pytest                                                            # тесты
```

Все подборы выполняются на validation, test считается один раз для итоговой таблицы. Результаты сохраняются
в `data/adilet/*.json`.

**Дообучение реранкера в Colab.** На Google Drive нужно заранее загрузить дообученную e5 — архив

## Ограничения

- **Происхождение вопросов.** Вопросы датасета сгенерированы по тем же текстам, по которым идёт поиск, — метрики,
  вероятно, выше, чем на реальных пользовательских запросах.
- **Устаревшие акты в датасете.** Четыре из 14 актов утратили силу, Конституция 1995 года заменена новой, из Гражданского
  кодекса есть только особенная часть. Метрики это не искажает, но в режиме датасета система может ответить по отменённому
  акту (REPORT.md, раздел 2.4). Для реального использования предназначен корпус «Законы для граждан».
- **Корпус «Законы для граждан» не оценён:** к нему нет размеченных вопросов, а разговорные формулировки поиск может
  находить хуже (REPORT.md, раздел 7.13).
- **Автоматические эталоны.** Эталонный чанк определяется по совпадению слов ответа с текстом; доля неверных
  эталонов — около 3–5%. В протоколе A (`run_adilet_eval.py`) разметка проще (первые 45 символов ответа),
  поэтому его цифры напрямую не сравниваются с таблицей выше.
- **Чанк не знает своей статьи.** Окно 500 символов часто отрезает заголовок статьи; это главная причина ошибок
  итоговой системы (REPORT.md, раздел 7.10).
- **Один язык дообучения.** Дообучение и подбор параметров выполнены для русской части; казахская использует
  исходные модели и BM25 по умолчанию. Реранкер дообучен в одном запуске (разброс по seed не оценён).
- **Название акта в датасете.** Поле `source_title` не соответствует тексту у 9 из 14 документов; веб-демо берёт
  названия из шапки страницы adilet.zan.kz, `prepare_adilet_data.py` и бенчмарк — из поля датасета.
- **Структурный чанкер** (`get_structural_chunks`) в бенчмарке Adilet пока не используется — только в `run_real_data.py`.
- **Генерация ответа** проверяет, что сведения ответа есть в тексте закона, но не может проверить, что взят нужный
  пункт; оценена для русского языка и одной модели. Во время `eval_generation.py` видеопамять 4 ГБ занята почти
  полностью — параллельно запускать веб-демо или `ask.py --generate` не стоит.
