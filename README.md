# RAG Retrieval Evaluation

Исследовательский проект, сфокусированный исключительно на оценке **Retrieval-части** (информационного и семантического поиска) RAG-систем для нормативно-правовых актов (НПА) Республики Казахстан без использования генеративных моделей (LLM).

## Цель проекта
Сравнение эффективности различных моделей эмбеддингов, стратегий разбиения текста на фрагменты (чанкинга) и методов поиска (Dense FAISS, Sparse BM25, Hybrid RRF) для нормативных документов на русском и казахском языках.

## Поддерживаемые методы поиска
1. **Dense Retrieval (Векторный поиск):** плотные векторные представления на базе Transformer-моделей семейства `E5` с индексированием в `FAISS` (IndexFlatIP).
2. **Sparse Retrieval (Лексический поиск):** алгоритм `Okapi BM25` с адаптивной юридической токенизацией для точного поиска номеров статей, законов и числовых норм.
3. **Hybrid Retrieval (Гибридный поиск):** устойчивое слияние списков выдачи через алгоритм `Reciprocal Rank Fusion (RRF)`.

## Модели эмбеддингов
| Модель | Роль | Лимит | Размер вектора |
|---|---|---|---|
| `intfloat/multilingual-e5-small` | основная (по умолчанию) | 512 токенов | 384 |
| `intfloat/multilingual-e5-base` | для сравнения (`--model`) | 512 токенов | 768 |

Обе модели асимметричные: запросы получают префикс `query: `, документы — `passage: ` (добавляется автоматически).

## Метрики качества
Оценка качества поиска производится с использованием стандартных метрик Information Retrieval:
- **HitRate@k (Accuracy@k)** — доля запросов, для которых хотя бы один релевантный документ найден в топ-$k$.
- **MRR (Mean Reciprocal Rank)** — средняя взаимная позиция первого релевантного документа.
- **Recall@k** — полнота поиска среди топ-$k$ документов.

## Установка и запуск

### 1. Клонирование репозитория
```bash
git clone https://github.com/DamirKx/rag.git
cd rag
```

### 2. Создание и активация виртуального окружения
```bash
python -m venv venv

# Windows:
venv\Scripts\activate

# Linux / macOS:
source venv/bin/activate
```

### 3. Установка зависимостей
```bash
pip install -r requirements.txt
```

### 4. Подготовка данных (Adilet Legal QA)
Скрипт автоматически загружает датасет `olzhasAl/adilet-legal-qa-kz` с Hugging Face Hub, очищает текст от артефактов веб-парсинга (шапки и подвалы страниц) и формирует выборки:
```bash
python prepare_adilet_data.py --lang all --test-size 200
```

### 5. Запуск оценки поиска
Бенчмарк сравнивает две стратегии чанкинга — **фиксированное окно** (500 символов, перекрытие 50) и **контексты датасета целиком** (каждый контекст Adilet QA — фрагмент закона длиной ~5–6 тыс. символов) — и для каждой из них три метода поиска: **Dense**, **BM25** и **Hybrid**.

Эмбеддинги кэшируются в `data/adilet/cache/`. В имя файла кэша входит отпечаток (SHA-256) индексируемых текстов, поэтому при изменении корпуса векторы пересчитываются автоматически.
```bash
# Оценка на русском языке (100 вопросов, топ-3):
python run_adilet_eval.py --lang rus --test-size 100 --top-k 3

# Оценка на казахском языке:
python run_adilet_eval.py --lang kaz --test-size 100 --top-k 3

# Сравнение с e5-base:
python run_adilet_eval.py --lang rus --model intfloat/multilingual-e5-base
```

### 6. Интерактивный поиск по законам (CLI)
Вы можете задавать любые произвольные вопросы по законодательству в интерактивном консольном режиме:
```bash
# Запуск гибридного поиска (Dense FAISS + Sparse BM25):
python ask.py --mode hybrid

# Только семантический поиск:
python ask.py --mode dense

# Только поиск по номерам статей и ключевым словам:
python ask.py --mode bm25
```
Во время работы режим переключается командой `:mode dense|bm25|hybrid`, выход — `q`.

### 6.1. Веб-демо поиска (Streamlit)
```bash
streamlit run app.py
```
Откроется страница в браузере (http://localhost:8501). Возможности:
- выбор языка корпуса (рус / каз), метода поиска (Hybrid / Dense / BM25) и модели (базовая или дообученная из `models/`);
- поиск по чанкам 500 символов с подсветкой слов запроса, номером статьи и ссылкой на документ на adilet.zan.kz;
- фильтр по законам и вкладка «Сравнение методов» (топ-3 каждого метода на один вопрос).

При первом запуске для казахского корпуса эмбеддинги вычисляются несколько минут, затем берутся из кэша.

> **Важно:** поле `source_title` в датасете Adilet Legal QA не соответствует тексту у 9 из 14 документов
> (например, `Z950002444_` подписан как «О хозяйственных товариществах», а это Закон «О банках и банковской деятельности»).
> Веб-демо берёт названия из шапки исходной страницы adilet.zan.kz; `prepare_adilet_data.py` и бенчмарк пока используют поле датасета.

### 7. Тесты
```bash
pytest
```

## Известные ограничения
- **Лимит длины модели.** Контексты датасета занимают ~1100 токенов, а модели E5 читают только первые 512 — остаток при векторизации в стратегии «контексты целиком» отбрасывается.
- **Эталон для фиксированного чанкинга.** Релевантный чанк ищется по первым 45 символам сгенерированного ответа; если совпадение не найдено, релевантными считаются все чанки исходного контекста. Поэтому Recall@k двух стратегий напрямую несопоставим.
- **Происхождение вопросов.** Вопросы датасета сгенерированы по тем же текстам, по которым идёт поиск, что завышает метрики относительно реальных пользовательских запросов.
- **Структурный чанкер** (`get_structural_chunks`) поддерживает заголовки «Статья N.» и «N-бап.»; дополнительное разбиение на пункты выполняется только для русскоязычных статей о внесении изменений («1. В Закон…»). В бенчмарке Adilet QA он пока не используется — только в `run_real_data.py`.
